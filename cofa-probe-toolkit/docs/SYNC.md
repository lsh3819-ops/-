# 실제 설치 목록을 나중에 동기화하기

현재 목록은 비어 있으며, 실제 설치 확인이나 백업은 수행하지 않았습니다. 아래 절차는 사용자가 검토한 파일만 수동으로 보관하기 위한 것입니다.

## 1. 로컬에서 목록 확인

Codex에서 사용 가능한 스킬 목록과 설치 출처를 확인합니다. 플러그인 제공 스킬, 시스템 기본 스킬, 직접 추가한 스킬을 구분합니다. 현재 프로젝트의 `.agents/skills`와 사용 중인 버전의 사용자 스킬 위치를 확인하되, 전체 설정 디렉터리를 저장소로 복사하지 않습니다.

CLI를 사용하는 경우 `codex mcp list`로 MCP 이름을 로컬에서 확인합니다. 출력에 주소나 경로가 포함될 수 있으므로 결과를 그대로 커밋하지 않습니다. 플러그인이 제공하는 MCP는 직접 설정한 서버와 관리 방식이 다를 수 있습니다.

## 2. 보관할 내용 선별

- 스킬: 출처 URL, 고정 revision/tag, 라이선스, 검토일을 기록합니다. 재배포가 허용된 SKILL.md와 필요한 리소스만 별도 검토 후 추가합니다.
- MCP: 이름, 배포 출처, 버전, transport, 필요한 환경변수 **이름**만 기록합니다. 토큰 값, 인증 헤더, 세션 쿠키, 개인 경로는 제외합니다.
- 원본 설정의 URL에 포함된 사용자명, 내부 호스트, 쿼리 문자열 인증정보도 제거합니다.
- 시스템·플러그인 파일은 통째로 복사하는 대신 설치 출처와 버전을 기록합니다.
- `inventory.example.json`을 기준으로 `inventory.json`을 만들고 실제 확인한 항목만 입력합니다. 전체 목록을 확인하기 전에는 `installed_inventory_verified`를 false로 유지합니다.

## 3. 새 브랜치에서 검토 후 PR

저장소를 복제하고 저장소 루트에서 수행합니다. 아래 이름이 이미 있으면 고유한 새 이름을 사용합니다.

```sh
git switch -c chore/sync-reviewed-skills
git status --short
git diff -- cofa-probe-toolkit
```

선별한 파일만 개별 경로로 추가합니다. 전체 폴더를 무심코 추가하거나 강제 추가하지 않습니다. 예를 들어 검토한 목록 파일만 추가하려면:

```sh
git add cofa-probe-toolkit/inventory.json
git diff --cached --name-status
git diff --cached
```

추가된 파일의 전체 내용과 바이너리·첨부파일도 확인합니다. 비밀키, 토큰, 개인 경로, 내부 주소, 비공개 데이터가 없을 때만 커밋하고 새 브랜치를 push하여 PR을 엽니다. 기존 파일과 동명의 스킬은 diff로 비교하고 의도한 수정만 포함합니다.

`.gitignore`는 이 폴더 안의 일부 파일을 제외할 뿐 비밀정보 검사 도구가 아닙니다. 이미 추적되는 파일이나 다른 이름에 담긴 비밀정보를 차단하지 못합니다.

## 4. 다른 환경에서 복원

검토한 특정 커밋을 기준으로 스킬을 프로젝트의 `.agents/skills/<skill-name>/`에 복사합니다. 기존 파일이 있으면 먼저 비교합니다. MCP 예시에서 필요한 섹션만 로컬 Codex 설정에 병합하고 이름 충돌을 해결합니다. 인증은 각 환경의 로그인 또는 환경변수로 다시 설정하며 저장소에 값을 기록하지 않습니다.

`COFA_PRACTICE_MCP_TOKEN`은 환경변수 이름의 예시일 뿐입니다. 예시 파일은 .env를 자동으로 읽거나 서버를 설치하지 않습니다. 실제 토큰은 로컬 자격증명 관리 방식을 사용해 주입합니다.

MCP를 활성화한 후 목록 확인과 공개 자료를 대상으로 한 간단한 읽기 요청으로 연결을 확인합니다. 스킬은 합성 데이터로 검증하고 결과를 목록에 기록합니다. 구성 파일 구문 검사와 실제 인증·연결 성공은 별개의 검증입니다.
